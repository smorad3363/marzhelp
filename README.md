# MarzHelp

ربات مدیریت نمایندگان و کاربران `Marzban` با پشتیبانی اصلی از `MySQL`.

## نصب یا به‌روزرسانی

دستور زیر هوشمند است:

- اگر `MarzHelp` نصب نشده باشد، نصب کامل را اجرا می‌کند.
- اگر نصب قبلی وجود داشته باشد، از برنامه و هر دو دیتابیس نسخه پشتیبان
  می‌گیرد و سپس مهاجرت امن را اجرا می‌کند.
- فایل‌های تنظیمات و اطلاعات ربات حفظ می‌شوند.
- حساب کاربری `root` دیتابیس با دو حساب محدود اجرایی و مهاجرتی جایگزین
  می‌شود.
- وبهوک تلگرام با یک مقدار محرمانه ثبت می‌شود.

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/smorad3363/marzhelp/refs/tags/v2/bootstrap.sh)
```

این دستور نسخه ثابت `v2` را نصب می‌کند و فقط با `smorad3363/Marzban v4`
و schema سازگار شماره `1` ادامه می‌دهد. داده‌های MarzHelp در همان دیتابیس
Marzban نگهداری می‌شوند و backup عادی Marzban آن‌ها را نیز پوشش می‌دهد.

برای نصب یا بازگشت به یک نسخه مشخص، تگ را به اسکریپت بدهید:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/smorad3363/marzhelp/refs/tags/v2/bootstrap.sh) --version v2
```

شکل کوتاه زیر نیز همان نتیجه را دارد:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/smorad3363/marzhelp/refs/tags/v2/bootstrap.sh) v2
```

ورودی نسخه می‌تواند نام یک تگ یا شاخه معتبر باشد. اگر نصب قبلی وجود داشته
باشد، قبل از جابه‌جایی نسخه از کد و دیتابیس‌ها پشتیبان گرفته می‌شود.

## به‌روزرسانی مستقیم

برای سروری که از قبل به این مخزن منتقل شده است، دستور باید با دسترسی
`root` اجرا شود:

```bash
sudo bash /var/www/html/marzhelp/update.sh
```

نسخه‌های پشتیبان با دسترسی محدود داخل مسیر زیر نگهداری می‌شوند:

```text
/var/backups/marzhelp
```

## معماری و مهاجرت

جزئیات مدل امنیت، حسابداری ترافیک، تریگرهای ثابت و روش بازگشت در فایل زیر
آمده است:

`ARCHITECTURE.md`

## نکته شبکه

در نصب اولیه، درگاه `80` موقتاً برای دریافت گواهی `Let's Encrypt` استفاده
می‌شود. سرویس نهایی روی درگاه `88` در دسترس خواهد بود. نصب‌کننده تنظیم
پیش‌فرض `Nginx` یا سرویس `Apache` موجود را حذف نمی‌کند.
